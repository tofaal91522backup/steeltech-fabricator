**Product decisions made (not specified by the spec — please double-check these):**
1. **Issue status values don't match the old demo UI.** The real API has three statuses — `open`, `in_progress`, `closed` — not the old two-value `open`/`resolved`. Tabs and status badges were updated to the real three values. Sending a reply now sets `status: "closed"` (closest real equivalent to the old "mark resolved" behavior). If admins should be able to reply without closing, or move a ticket to `in_progress` separately, that needs a small follow-up (e.g. a status dropdown in the reply modal).
2. **Deletion requests have a `pending` state the old demo UI never showed** (it only had `unresolved`/`resolved`). Added a `Pending` tab and stat card. Because `PATCH .../deleted-report/` with `status: "resolved"` **permanently hard-deletes** the underlying report (per the endpoint's docs — irreversible, only the audit row survives), Approve/Reject actions are now only offered on `pending` requests, and "Approve" has a `window.confirm` guard warning about the irreversible delete. Previously-decided (`resolved`/`unresolved`) requests are now view-only — the old UI let you toggle a resolved request back and forth, which is no longer offered since re-approving an already-rejected request doesn't map to any valid API transition, and there's nothing left to delete on an already-resolved one.
3. **Fields with no real API equivalent were dropped**, not faked: the old demo had `requestNumber`, `email`, `userType` on deletion requests, and a separate `subject` on issues — none of these exist in the real payloads, so they were removed rather than left as dead/undefined bindings. Deletion requests now show the linked `report_snapshot` (invoice number, fabricator, distributor, amount, sales date) instead.
4. **No server-side search param is documented for `GET /administrator/issue-report/`** (only `status`, and pagination via `p`/`page_size`). The search box in `Issues.jsx` therefore only filters the currently-loaded page client-side, not the full dataset — a real fix needs either a confirmed `search` query param on that endpoint or a UX change (e.g. drop the search box, or fetch a larger page).
